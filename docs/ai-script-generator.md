# AI 口播稿生成器

## 定位

这个生成器服务于一个讲 AI 出海的短视频账号，目标观众是中国 App 出海开发者、独立开发者、增长负责人和产品团队。

内容重点：

- App 出海广告买量、素材策略、渠道变化
- 海外爆火 App、AI 产品和增长案例
- 订阅、内购、免费试用、价格实验和变现路径
- AI 工具如何帮助出海团队降本增效
- 小团队或独立开发者的海外产品机会

## 生成流程

首页点击 `AI 生成 3 篇` 后，前端会请求 `POST /api/scripts/generate`。

服务端会：

1. 使用 `OPENROUTER_API_KEY` 调用 OpenRouter。
2. 默认使用 `openai/gpt-5.5` 模型，也可以通过 `OPENROUTER_MODEL` 换成更快模型。
3. 通过 `openrouter:web_search` 快速检索近期真实热点，默认只取 3 条搜索结果，避免生成过慢。
4. 要求模型返回结构化 JSON。
5. 校验每篇稿件至少有一个真实来源 URL。
6. 校验每篇稿件的爆款自检：`viral_score >= 8` 且不能太小众。
7. 写入 `data/口播词/YYYY-MM-DD/*.md`。
8. 首页重新拉取列表，新稿直接出现在口播词列表里。

## 爆款机制

公开短视频方法论里反复出现几个共同点：黄金 3 秒要用钩子停滑，口播要围绕痛点、反差、数字、利益和情绪共鸣展开，内容要尽量减少自我介绍和行业黑话，并用完播、互动、收藏来倒推文案是否有效。

生成器现在按这套机制约束稿件：

- 首句必须有停滑点：数字冲击、反差判断、痛点提问、利益前置或反常识结论。
- 必须让观众觉得“这和我有关”：多讲“你的 App”“投放预算”“订阅用户”“出海团队”。
- 必须有冲突或信息差：例如装机很多但不赚钱、广告越来越贵、功能普通但订阅很强。
- 必须讲人话：英文缩写和行业术语要换成中文解释，解释不清就不要写。
- 一篇只讲一个核心观点，不塞太多数据。
- 结尾要有可转述的观点，让用户愿意收藏、评论或转发。

## 提示词方向

生成器会要求模型先搜索最近 7-30 天的信息，再生成口播稿。

每篇稿件需要：

- 220 到 320 中文字
- 第一段直接抛事件、数字或反常识判断
- 中段按“现象 -> 为什么重要 -> 普通出海人怎么学”推进
- 结尾给出对出海团队有用的明确观点
- 保留至少一个来源 URL，避免凭空编热点
- 保留爆款自检：评分、钩子、冲突/信息差、观众收益、通俗度、大众适配性

## 禁止项

- 不要无来源生成热点
- 不要虚构公司收入、下载量、融资、广告投放数据
- 不要写成新闻摘要
- 不要泛泛讲 AI
- 不要偏离 AI 出海、App 出海、广告买量、订阅内购和产品增长
- 不要选择普通观众听不懂的冷门功能或过窄行业新闻
- 不要堆英文缩写、平台功能名和专业指标
- 不要把文案写成研究报告

## 环境变量

在项目根目录创建 `.env.local`：

```bash
OPENROUTER_API_KEY=你的 OpenRouter API Key
```

`.env.local` 已被 `.gitignore` 忽略，不要把 API Key 写进前端代码或提交到仓库。

可选速度配置：

```bash
# 默认 openai/gpt-5.5。想更快可以换成你 OpenRouter 账号可用的轻量模型。
OPENROUTER_MODEL=openai/gpt-5.5

# 默认 60000，即 60 秒超时。
OPENROUTER_TIMEOUT_MS=60000

# 默认 3。越大越慢，但来源更充分。
OPENROUTER_SEARCH_MAX_RESULTS=3
```
